# BUILD_CONTRACT

## Frozen decisions (change only with a DECISIONS.md entry)
- D1 Gloam as the engine (credited, pinned)
- D2 Gloam final ceremony keys
- D3 Vouch and sweep leaves in ShaidaLedger, checked in-circuit
- D4 Groth16 + multi-party phase 2
- D5 Proof data in the URL fragment only
- D6 Licence mix
- Chain 44005, tUSD8 only; Shanghai; legacy txs.
- Circuit: 8 slots, depth 20, public signals exactly `ledgerRoot, asset, threshold, count, fromIndex, toIndex, context`.

## Never fabricate
- No placeholder data shown as real. Show `—` until a real value exists.
- No fallback that returns fake success (no hard-coded "VALID", no cached verdicts).
- No test counts, gas figures, timings or tx hashes before they are produced by a command.
- Demo personas (Ada, Acme Studio, Landlord Bola) and their payments are labelled as demo in the UI and docs.
- Evidence files are generated by scripts, never hand-written.

## No silent fallback
- Config validated at startup (addresses, chain ID, artifact hashes). Missing config → named refusal.
- No empty `catch`. Every caught error is mapped to a PRD §4 code or rethrown.
- Unknown tx outcome → `TxOutcomeUnknown`; check by hash or nullifier; never resend blindly.

## Traceable numbers
Every reported number (gas, proving time, counts) records: command, commit, environment (fork/44005, machine), date, and class (real / fork / simulated).

## Failures stay on record
Failed runs and refuted claims are kept in `evidence/` and CLAIMS.md (demoted, not deleted).

## Protected critical path (the gate must pass after any change here)
- `contracts/src/{PayerRegistry,ShaidaDepositor,ShaidaLedger,IncomeVerifier}.sol`
- `packages/shaida-proofs/circuits/income.circom` + zkey + generated verifier
- `packages/shaida-proofs/src/verify/*` (PRD §5 steps)
- `web/src/app/api/relay/*`, indexer
- deploy scripts and `deployments/aevum.json`

## Code bar
See CLAUDE.md "Conventions". In short:
- pure core
- strict schemas
- closed error codes
- discriminated unions for results
- fail closed (UNKNOWN is never success)
- behaviour-named tests with IDs
- property tests for the witness builder
- adversarial tests in `tests/adversarial/`

Planning quality does not excuse code quality.

## Gate
`make gate` from a clean clone:
1. install
2. forge build + Shanghai check
3. circuit compile + artifact hash check
4. typecheck + lint
5. unit, circuit and contract tests (X-suite)
6. fork tests against real tUSD8 (allowed to be marked inconclusive offline, never skipped silently)
7. CLAIMS.md check: README claims ⊆ PROVEN

1. Soundness: cheat suite X01–X13 refused, with codes

3. Ceremony record (phase 1 hash + contributions + beacon)
4. Live verify page: tamper attempts refused
5. Gasless deposit on real tUSD8
6. Proving time in a browser (S8), as measured
